# 定投台 · DCA Dashboard

五个标的的定投倍数看板：每天按固定规则算一次「当下该投几倍」，出静态页面 + Markdown 报告。

**核心原则：分数由规则机械算出，同一份数据必得同一分，可复现、可复盘。不经过 LLM。**

| # | 标的 | 评分用的数据 | 落地基金 | 说明 |
|---|---|---|---|---|
| 1 | 纳斯达克综合指数 | `.IXIC` 日线 | — | 仅作市场温度参考，不产生买入动作 |
| 2 | 纳斯达克100指数 | `.NDX` 日线 + 蛋卷 NDX 估值 | `000055` 广发纳斯达克100A | 跟踪误差 0.83%，六只候选中最低 |
| 3 | 黄金 | COMEX 主力连续 `101.GC00Y` | 自行选择 | 另附伦敦金现快照 |
| 4 | MSCI 全球医疗保健指数 | **MSCI 官方指数 106801**（NETR） | `000369` 广发全球医疗保健A | 官方接口，回溯至 1999 年 |
| 5 | 中证红利指数 | `000922` 日线 + 蛋卷估值 | `009051` 易方达中证红利ETF联接A | — |

### 为什么一律用指数、不用基金净值

基金净值有三重失真，任何一条都足以让趋势与回撤算错：

1. **分红/份额折算造成单日跳降** —— 160213 曾出现单日 −38.32%，用它算会得到「距高点 −52.4%」，而同期指数实际只跌 4.5%。
2. **QDII 净值 T+1/T+2 披露，日期与指数错位一天** —— 不修正直接对比，年化跟踪误差会算成 20%+（实测：修正后 0.83%）。这也顺带给出了各基金的跟踪精度。
3. **管理费与申赎冲击持续侵蚀净值** —— 长期跑输指数，会把「便宜」误判成「更便宜」。

### 分数方向

0–100，**越高越该买**（越便宜 / 越恐慌）。50 分 = 1.0 倍基准。

### 倍数表

| 分数 | 倍数 | 含义 |
|---|---|---|
| ≥82 | 2.0× | 明显低估，加倍 |
| 68–82 | 1.5× | 偏便宜，加码 |
| 56–68 | 1.2× | 温和加码 |
| **40–56** | **1.0×** | **中性，基准（16 分宽）** |
| 28–40 | 0.8× | 偏贵，略减 |
| 14–28 | 0.5× | 贵，减半 |
| <14 | 0.3× | 极度高估，只留底仓 |

中性带 16 分宽（v2 是 10 分），避免分数抖 1 分就换档。同档多标的时看**档内位置**排先后。

### 四个维度

| 维度 | 含义 | 权重（按资产类型不同） |
|---|---|---|
| 估值 | PE/PB 分位、股息率分位、比价分位 | 红利 40% / 医疗 35% / 纳指 30% / 黄金 15% |
| 趋势 | 距 200 日均线偏离、距 52 周高点回撤 | 黄金 30% / 纳指 25% / 红利 20% |
| 情绪 | 20 日年化波动率、成交额放量或 60 日动量 | 黄金 25% / 纳指 20% / 红利 15% |
| 宏观 | TIPS 实际利率 70% + 名义利率 30%（红利：相对沪深300 强弱 + 沪深300 PE 分位） | 黄金 30% / 红利 25% / 纳指 25% |

黄金没有 PE，估值权重压到 15%，把权重让给趋势与宏观。

> **宏观维度为什么没有美元指数？** 不是遗漏。DXY 和 USDCNH 的历史序列只能从东财的
> `100.UDI` / `133.USDCNH` 拿到，而这两个 secid 在 GitHub Runner 上**必断连**（本地正常）。
> 一旦用它打分，同一天本地算 39.5 分、云端算 34.0 分，倍数从 1.0 变 0.8——**分数不能取决于跑在哪台机器上**。
> 已验证的替代源全部不可用：新浪外汇旧接口返回空数组、Stooq 需要 JS 校验、Yahoo Finance 返回 403、FRED 本地被墙。
> 所以这两项降级为「仅展示」，宏观只用美国财政部官方利率（实际利率本身就是美股估值的核心变量）。

### 闸门（优先级高于分数）

1. 数据完整度 < 70% → 强制 1.0×
2. 深度破位（跌破年线且年线转头向下）→ 倍数封顶 1.0×
3. 估值或情绪维度极端（<10 或 >90）→ 提示复核数据

**申购状态不参与打分、不改倍数。** 同一份行情不该因为渠道临时限购给出不同倍率——限购只影响「钱能不能落到那只基金」，单独列在执行方案里。

## 三、目录结构

```
dca-dashboard/
├─ config.json              标的口径、权重、倍数表（改配置不改代码）
├─ run_daily.py             每日跑批入口：抓数 → 算分 → 写快照 + 报告
├─ backfill.py              用同一套规则重算过去 N 个交易日（不造假，as_of 截断防前视）
├─ build_site.py            汇总快照 → docs/index.html（数据内联，前端零 fetch）
├─ src/
│  ├─ net.py                带退避重试的 HTTP 层（纯标准库）
│  ├─ sources.py            各数据源封装，只负责取到干净数据
│  ├─ engine.py             分位/回撤/波动/对数趋势残差 + 综合分 + 倍数 + 闸门
│  ├─ compute.py            五个标的的维度组装
│  ├─ recent.py             近一月涨跌轨迹 + 近 7 天涨跌（纯展示，不参与打分）
│  ├─ labs.py               长期锚 / 创红比 / 二十二年双线（纯展示，不参与打分）
│  ├─ signals.py            阈值提示条（纯派生，不改分数）
│  ├─ history.py            分数历史累积与序列化
│  ├─ render.py             Markdown 报告
│  └─ site_template.py      HTML 模板（手写 SVG 图表，不引 CDN）
├─ tools/
│  ├─ selfcheck.py          交付前自检
│  ├─ push_github.py        走 REST API 推送（本机到 github.com 被代理拦）
│  ├─ shot.py               本地截图：定位到某个区块（JS 渲染的也能拍）
│  └─ peek.py               本地截图：单独渲染某个静态区块
├─ data/
│  ├─ cache/                接口缓存（6 小时 TTL）
│  └─ out/                  每日快照 YYYY-MM-DD.json + latest.json + report.md
└─ docs/                    GitHub Pages 站点（Pages 只能指向根目录或 /docs）
```

## 四、本地运行

无第三方依赖，只要 Python 3.10+。

```bash
python run_daily.py            # 跑一次，写 data/out/
python run_daily.py --dry      # 只打印不落盘

python backfill.py 120         # 回填最近 120 个交易日（已存在则跳过）
python backfill.py 120 --force # 强制重算

python build_site.py           # 生成 docs/index.html
```

## 五、自动跑批

`.github/workflows/daily.yml`：**每个交易日跑 13 次**（北京时间），结果 commit 回仓库，Pages 自动更新。

| 时间（北京） | 用途 |
|---|---|
| 06:37（周一~周六） | 美股收盘（北京 04:00）后 2.5 小时，专门抢 **MSCI / 美股隔夜收盘** |
| 08:07（周一~周六） | 主批次：美股已收盘、A 股未开盘，当天的倍数可以照着执行 |
| 09:37 / 10:07 / 10:37 / 11:07 / 11:27 | A 股早盘，每半小时（11:30-13:00 午休不跑） |
| 13:07 / 13:37 / 14:07 / 14:37 / 14:57 | A 股午后，每半小时（14:57 贴尾盘） |
| 15:17 | 收盘后最终值，覆盖当天前面所有记录 |

### 三种更新节奏，别混为一谈

页面上一共三层数据，速度上限完全不同：

| 层 | 频率 | 为什么只能这样 |
|---|---|---|
| **实时价格** | **每 60 秒**（浏览器直连腾讯行情） | 纯前端，不落库、不影响历史，想多快都行 |
| **美股市场情绪**（CNN F&G） | **每 60 秒**（浏览器直连 CNN） | 接口允许跨域，前端能直拉；但数据本身日频，数字多数时候不变 |
| **MSCI 全球医疗** | 每交易日 06:37 / 08:07 跑批 | 没有公开实时源，只能等官方 EOD 收盘数据 |
| **分数 / 倍数 / 所有曲线** | 每交易日 13 次（GitHub Actions） | 见下 |

> 这三层在页面上是**显式标注**的，不用猜：实时行情条每个格子带绿色「实时」标、
> MSCI 那格带「EOD + 日期」标，分数派生的数字带「快照」标，宏观那排带「日频」标，
> 每个区块标题右侧有「每交易日 13 次 / 随跑批刷新」徽章。
> 加这些徽章的原因是：顶部那条每分钟在动的行情条，很容易让人以为整页都在实时跑。

**MSCI 全球医疗为什么只能到日频**：它是 MSCI 官方指数，没有免费实时行情源
（腾讯/新浪只覆盖 A 股、美股个股与主要海外指数，不含 MSCI 行业指数）。
官方 `getLevelDataForGraph` 接口给的是 EOD（日终）点位，北京时间大约次日凌晨到早上可取。
所以它固定标「EOD + 日期」，并在实时条下方写明「每交易日 06:37 / 08:07 跑批时更新」——
这句话必须写，否则那个日期看起来像永远卡住不动。

**分数做不到 1 分钟一次**，三个硬限制：

1. **一次跑批实测 2~3 分钟**（美债 5956 天 CSV + MSCI 官方 + 中证官网 + 新浪 + 蛋卷）。
   1 分钟一跑 = 这次还没结束下次就排队，`concurrency` 会自己堵死自己。
2. **分数用的全是日频数据**：PE 周频、股息率、40/90 月均线、财政部利率日频。
   日内只有「价格」那一维在动，每分钟重算得到的分数变化 < 0.5 分，没有信息增量，
   只会把接口拉到限流。
3. **GitHub cron 最小粒度是 5 分钟，且不保证准时**（高负载会 delay 甚至 drop），
   当不了实时用。真要秒级只能自建常驻服务，那是另一个成本量级。

**半小时是这套体系的实际上限**：盘中价格在动，分数确实会跟着变，半小时能跟上；
再往密压只会把接口拉到限流、把 Pages 重建次数堆上去，而分数变化也就 0.3~0.5 分，
跨不了档（中性带宽 16 分）。

### 几个必须知道的坑

- **cron 不要写 :00 / :30**：GitHub 官方明说 schedule 是「尽力而为」，整点/半点是全网最挤的时刻。
  2026-10-24（周六）08:30 那次就是这么丢的——工作流 `state` 仍是 `active`、没有任何失败记录，就是没触发。
  所以 13 个时刻的分钟数全用 07 / 17 / 27 / 37 / 57。
- **页面是静态的，跑批更新后已打开的页面不会自己变**：每 3 分钟探一次 `data.json` 的
  `generated_at_ts`，发现比当前快照新就在页头弹一条「后台已更新到 HH:MM，加载新数据」。
  `file://` 下 fetch 会被同源策略拒绝，这种情况直接跳过（本地预览不需要）。
- **数据日 = 行情实际截止日，不是运行日**：周末跑批如果用运行日，会往历史里写一期「周六」的分数
  （内容与周五相同），分数曲线多一个不存在的点、周一的环比也会算错。
  `run_daily.py` 取各标的 `price_date` 的**中位数**（排除 24 小时交易的黄金，否则会把数据日往前拽）。
- **美股不会被打成盘中价**：美股时段是北京 21:30–04:00，最早一次跑批是 06:37，
  抓到的永远是「最近一个已收盘」。
- **MSCI 全球医疗没有实时源**：腾讯/新浪不覆盖 MSCI 行业指数，只能用官方 EOD。
  实时条上那一格固定标「EOD + 日期」，并在下方写明「06:37 / 08:07 跑批时更新」——
  不写这句话，那个日期看起来就像永远卡在昨天。
- **同日多次跑批不会污染历史**：`src/history.py::append()` 按 `trade_date` 覆盖，一天只留一条，
  最终以 15:17 收盘后那次为准。
- **页面会自己报告「是否跟上节奏」**：跑批时刻表由 `src/sched.py` 从 workflow 的 cron 解析出来
  （不是在前端写死一份，否则改 cron 忘改 JS 就会显示错误的下次更新时间），
  页面头部显示「上次 08:07 未触发 · 下次 周一 08:07」。
  判断依据是「生成时间有没有晚于上一个计划时刻」，而不是「几小时没更新」——
  后者在周末必然误报（周五 15:17 到周六 08:07 本来就有 17 小时空档）。
- **时间戳带时区**：`generated_at` 是北京时间，另有 `generated_at_ts`（epoch 秒）供页面算新鲜度；
  之前直接 `datetime.now()` 在 Runner 上是 UTC，页面上差 8 小时。

- **手动跑一次**：Actions → `daily-dca` → Run workflow（2026-10-22 实测全绿，约 2 分 40 秒）
- **跑批会自己卡住不放行**：`tools/selfcheck.py` 不通过就不提交，避免把坏数据推到线上
- **数据源健康探针**：`tools/probe_ci.py` 每天先跑一遍，逐个打印各接口状态（仅展示，不阻断）
- **跨环境一致性（2026-10-22 实测）**：同一份行情，本机与 GitHub Runner 算出的分数差 ≤0.2 分，
  倍率完全相同、完整度均为 100%。0.2 的差异来自两次抓取时点不同（盘中最后一根 K 线）。
  这一条是有意设计的：**分数不允许取决于跑在哪台机器上**，为此剔除了只有本机能取到的输入（见上文宏观维度说明）。

### 分数历史曲线（每天自己长一格）

曲线不是写死的图，是**每交易日累积 1 期**的 `data/history.json` 画出来的：

```
run_daily.py  →  src/history.py::append()  写/覆盖当日一条 {d, a:{id:{s,m,p}}}
              →  git add -A 自动 commit（仓库里只留这一份几十 KB 的累积文件，data/out/*.json 不进仓库）
              →  build_site.py 读它 → 内联进 docs/index.html → Pages 自动重建
```

- 2026-04-24 起的 120 期是 `backfill.py` 按 `as_of` 逐日截断回填的（无未来函数），此后每天追加一格
- 图表工具条可切 **近 1 月 / 近 3 月 / 全部 N 期**，也可用 `?w=22` 直接打开某个窗口
- 右侧「较上一期」是各标的当日分数相对上一期的变化，图例里跟的是最新分数
- **每条曲线的右端直接标「指数名 + 当前分数」**（2026-10-24 用户提出：只有数字时认不出哪条线）。
  四条线经常收在 35–52 这十几分里，末端几乎重合，所以按 y 排序后逐个压开最小间距；
  **被压开的画一小段引线连回真实端点** —— 不画引线，标签看着像标到了旁边那条线上，比不标更糟。
  - 右侧留白按最长的名字动态算（`tw()` 估字宽），不再写死 16 单位；超了用 `ellip()` 截断。
  - 窄画布（430）一行放不下，改名称在上、分数在下两行，块间距放大到 1.5 倍块高。
  - 名称与分数放同一个 `<text>` 的两个 `<tspan>`（`dx="4"` 出间距），位置交给排版引擎，
    不用自己估字宽去摆第二个 `<text>`。
  - 图例仍然保留分数：它同时是配色对照表，滚到底能一次看全四个数。
- 窗口切换只重算前端 y 轴范围，不改变任何分数；末值标签跟着重排（引线也重算）
- **画布宽度会看屏幕**：`innerWidth < 640` 时用 430×350 的 viewBox，桌面用 1100×330。
  之前统一用 1100 宽，在 375px 手机上被缩到 1/3，线只剩 0.7px、字只剩 3px —— 这才是「手机上图太浅」的根因，
  光调配色解决不了。横竖屏切换会触发重画（`resize` 防抖 200ms）。
- 图上方固定写明方向：**分数越高 = 越便宜 = 建议买得越多**，金色虚线标注「1.0× 基准 · 50 分」
  （标签放左端并加白色描边，放右端会被收口的几条线压住）。

### 实时行情条（`#live`，只显示价格，不参与打分）

页面顶部六个格子：纳指综合 / 纳指100 / 黄金 COMEX / 中证红利 / 沪深300 取实时价，MSCI 全球医疗没有公开
实时源，明确标「收盘 + 日期」而不冒充实时。

- 浏览器直连 `https://qt.gtimg.cn/q=...`（`<script>` 跨域，不需要 CORS），每 60 秒刷新一次
- **解析坑**：A 股时间戳是 14 位紧凑格式（`20261023120549`）、美股带横线；不能从前往后找日期 ——
  成交量字段 `37926310` 也是 8 位数字，会被误判成日期导致涨跌幅恒为 `0.00%`。改成**从后往前**匹配。
- 接口取不到就整块 `display:none`，绝不影响分数和倍数（两者完全解耦）。

### 阈值提示（`src/signals.py`，只标位置、不改倍数）

页面顶部那几条提示是**纯派生**的：读 latest（分数/倍数/长期锚）+ `history.json`，不改任何分数，也不参与算分。
阈值全部写成常量、在页面上原样公开（「阈值口径」一行），有就报、没有就报「离提示线还有多远」——

| 规则 | 触发条件 | 级别 |
|---|---|---|
| A 换档 | 本期倍数 vs 上期变化 ≥0.15 | 加重 |

| C 极值 | 分数 ≤28 或 ≥82 | 加重 |
| D 连续 | 连续 3 期 ≤28 分（排除单日抖动） | 加重 |

### 近一月涨跌（`src/recent.py`，只展示价格、不参与打分）

两处呈现，数据同源（`latest.assets[].month`）：

1. **每张标的卡片**里的走势条：近一月累计涨跌曲线 + 近 7 天那一段加粗 + 末点，前端 JS 画。
2. **「近一月涨跌」板块**的对比图：5 条线归一化到 0%，右侧灰底标出最近 7 个自然日，
   每条线的末端直接写「指数名 + 近一月涨跌幅」（不带名字的话只能靠颜色猜是哪条），服务端出 SVG。

口径：

- 窗口按 **自然日 30 天**回溯，取窗口内所有交易日。基准 = 窗口**首个交易日**的收盘，
  所以曲线首点恒为 0% —— 和「近一月涨幅 = 现在 / 一个月前 − 1」的通行定义一致。
- **近 7 天也按自然日算**，页面上同时给出覆盖的交易日数（本期是 5 个）。
  把它当成「7 个交易日」会多出 3～4 天，是这类图最常见的口径错位。
- 涨红跌绿（A 股习惯），和分数那套金色/灰色配色**完全无关** —— 分数是「贵不贵」，这条线是「最近涨没涨」。

写这块踩过的点：

- **横轴必须按真实日期铺，不能按数据点索引**。同样「近一个月」，美股 23 个点、中证红利只有 17 个点
  （10 月长假）。按索引画会把两条线压成同样长度，看着「同起点同终点」，其实时间跨度根本不一样 ——
  这是这类对比图最容易骗人的画法。
- **末值标签会叠**：两条线末端差 0.9 个点（≈13px）就糊成一坨。所以标签单独一轮画：
  按 y 排序后逐个压开最小间距，推到底边外再整组上移。
- **末值标签必须带指数名**。原来只画 `+6.02%`，靠颜色对线，5 条线挤在一起根本认不出谁是谁
  （2026-10-24 用户提出）。现在写成 `MSCI 全球医疗保健指数 +6.02%`：名称用同色但淡一档、字号小一号，
  百分比加粗，读起来是一个整体。
  - 右侧留白不能写死 54 了，改成按**最长的那个名字**算（`_tw` 估字宽，CJK 1em / ASCII 0.55em），
    上限 `0.34×画布宽`；超了就用 `_ellip` 截断加省略号，绝不让文字顶出 `viewBox`。
    留白少算几个单位，名字就会被画布边缘裁掉 —— 这是加名字时第一次改出来就踩到的。
  - 名字先去掉括号补充说明（`黄金（COMEX 主力连续）` → `黄金`），一个 12 字的括号尾巴能吃掉 1/10 绘图区。
  - **窄画布（430 单位）一行放不下**，自动改成两行：名称在上、百分比在下（`stack = w < 600`）。
    两行模式下块间距放大到 1.5 倍块高 —— 名字和自己的数字贴紧、跟邻居拉开，
    否则「上一块的数字」看着像「下一块的名字」，等于没解决原问题。
  - 一行模式里名称和百分比放在**同一个 `<text>` 的两个 `<tspan>`** 里，位置交给排版引擎算。
    自己估字宽去摆第二个 `<text>` 一旦估错两个就叠住了（第二个 tspan 用 `dx="4"` 出间距，
    不靠空格 —— 首尾空白会被 SVG 吃掉）。
  - **被压开的标签要画一小段引线**连回真实端点（`stroke-opacity=".45"`、6 单位长）。
    不画的话标签看着像标到了旁边那条线上，比不标更糟。分数历史图同理。
- **y 轴刻度不能「均分四段」**：均分出来是 -10.2% / -5.5% / -0.8% / +3.9% 这种读不出信息的数。
  改成 1/2/2.5/5 ×10^k 的整齐步长（`_nice_ticks`），末位是整数就不带小数点。
- 卡片里的走势条用 `preserveAspectRatio="none"`（横向铺满卡片）+ `vector-effect="non-scaling-stroke"`
  （线宽不跟着拉伸）。末点不能用 `<circle>`——会被横向拉成椭圆，改用零长度路径 + 圆头描边。
- 卡片是 JS 拼 `innerHTML` 出来的，SVG 直接串进字符串最省事；用 `<canvas>` 反而要额外管尺寸和重绘。

### 美股市场情绪（CNN Fear & Greed，只展示、不参与打分）

页面顶部行情条下面那块「美股市场情绪」，数据来自 **CNN Business 恐惧与贪婪指数**，
`src/sources.py::cnn_fear_greed()`。

**怎么刷新**：两层。

1. 跑批时抓一次，写进快照 → 页面首屏直接用服务端渲染好的值（保证有内容，不依赖 JS 和网络）；
2. **打开页面后每分钟直连 CNN 再拉一次**。接口带 `Access-Control-Allow-Origin: *`，
   浏览器可以直接 fetch（2026-10-24 实测：19ms 返回、gzip 后 29KB）。
   拿到新值就把分数、档位、指针位置、区间高亮一起换掉；
   拉不到（跨域被拦 / 网络抖动 / 接口改版）就**静默保留快照**，旁边显示「直连 CNN 暂不可用」。
   页面切到后台时暂停，切回前台立刻补一次。

**但它本身是日频**：CNN 这个指数在美东收盘后更新一次，所以大多数时候每分钟拉到的都是同一个数。
每分钟轮询的意义是「它一更新页面就反映」，不是「数字每分钟在跳」——这一点页面上也写着，
免得用户盯着不动的数字以为坏了。

**为什么不参与打分**：它衡量的是美股情绪，不是估值。本站五个标的的分数一律由指数自身的
「估值 / 趋势 / 情绪 / 宏观」四维算出，把 F&G 混进去会让口径变成大杂烩。

**分档口径（0-24 / 25-44 / 45-55 / 56-75 / 76-100）不是照抄网页，是从 251 天历史数据反推的**：
实测极端恐惧最高到 24.77、恐惧 25.26~44.86、中性 45.23~54.97、贪婪 56.20~71.17，
边界就是 24 / 44 / 55 / 75。网上流传的「0-25 / 26-49 / 50 / 51-74 / 75-100」是旧版口径，
按那个画会出现「指针在恐惧区、文字写极度恐惧」的自相矛盾。

每个区间对应什么情况（页面上一句话一条，当前所在那行高亮）：

| 区间 | 一句话 |
|---|---|
| 0-24 极度恐惧 | 恐慌性抛售、避险情绪拉满。长期看常是布局区，但短期可能继续跌 —— 便宜还能更便宜。 |
| 25-44 恐惧 | 多数人观望，情绪偏谨慎。通常还没到最悲观的时点。 |
| 45-55 中性 | 多空接近平衡，情绪本身不构成信号。 |
| 56-75 贪婪 | 追高的人变多，最容易在「再涨一点就加仓」的预期里买在高位。 |
| 76-100 极度贪婪 | 几乎没人相信会跌，历史上多出现在阶段性顶部附近。 |

另外还显示：昨收 / 一周前 / 一月前 / 一年前四个对照值（看情绪在往哪个方向走），
以及「往下拉最多 / 最不悲观」是哪两个子指标（从 7 个分项里取 min/max）。

**抓取这块有个坑**：CNN 的 WAF 会拦 `urllib`，必须用 `http.client` 手写请求，三点缺一不可：

1. header 名保留原始大小写 —— `urllib` 会把它规范成 `User-agent`（大写 A、小写 g），一变就判 bot（HTTP 418 teapot）；
2. **不要发 `Accept-Encoding`** —— `urllib` 默认追加 `identity`，同样触发拦截；`http.client.putrequest(skip_accept_encoding=True)` 才行；
3. `ssl.create_default_context()` 对这个域名握手会超时，必须 `set_ciphers("DEFAULT:@SECLEVEL=1")`。

所以 `cnn_fear_greed()` 不能改成 `net.fetch`，改了就挂。返回值里的 `sp500/sp125`、`vix/vix_50` 是同一指标的两个版本，取一个即可（否则 7 个分项会显示成 9 个）。

### 观察型模块（`src/labs.py`，不参与打分）

页面下半部分的三块长期指标，来自用户给的两张图，每天随跑批重算：

| 模块 | 内容 | 数据来源 |
|---|---|---|
| 中证红利 · 月线锚 | 月收盘 vs 40 月均线（估值中枢）、90 月均线（深度低估参考点）+ 偏离分位 | csindex 000922 全历史日线 → 按月取最后交易日 |
| 创业板指 ÷ 中证红利 | 比值现值、历史分位、区间、0.3 参考线 | 新浪 sz399006 ÷ csindex 000922 |
| 二十二年，两条线 | 沪深300全收益（蓝）vs 全市场（黑），日频、对数轴 + 三个年化 | csindex H00300 / 000985 / H00985 |

「二十二年」那张图带 **近 1 年 / 近 5 年 / 近 10 年 / 全部 22 年** 四个窗口：服务端一次性把 4 份 SVG 都生成好，
前端只切 `hidden`（不重算、不请求）。数据是**日频**（5296 个交易日，2004-01-01 起），每个窗口单独抽稀：
窗口越短保留越细（近 1 年全部 245 个点），越长抽得越狠（全部 900 个点），否则 5000 多个点在现代浏览器里画得动、
但 HTML 会白胖几十 KB。

宽屏和窄屏各生成一份画布（1060 单位 / 430 单位），用 CSS 媒体查询二选一 —— 一份固定宽度的 SVG 被缩到手机宽度时，
10px 的字会变成 3px，图就废了（这个坑在分数图上已经踩过一次）。

写这几块时踩过的点：

- **万得全A(800707.WI) 拿不到**：它是 Wind 商业数据，2026-10-23 实测东财搜索 `TotalCount=0`、东财行情三个 secid 全 `Remote end closed`、同花顺 404、腾讯 `pv_none_match`、雪球 400，新浪也没有。所以**没法"原样"画那根黑线**，改用中证全指 **000985 价格指数**近似：同为价格口径、同为基点 1000、同样覆盖全 A 股，量级（当前 5,154 点）和形态与截图一致。**不是替代成别的指数还假装是万得全A —— 页面图注里写明了原图是哪根线、现在画的是哪根。**
- 黑线是**价格**指数、蓝线是**全收益**指数，一条不含分红一条含。所以只能比形态和斜率，比收益高低要看「同口径全收益」那行（全市场 H00985 vs 沪深300 H00300）。
- 新浪 `sz399006` 单次只回 3000 条 → 创业板指只能回溯到 2014-06，创红比分位是「近 12 年」口径。
- 对数轴刻度不能一刀切用 1-2-3-5-7：22 年全貌（1000→7600）用粗刻度正好 5 根，但只看近 1 年（5154→7600）时粗刻度只剩 2 根，白花花一片。所以按 `vmax/vmin` 分档，窄区间换 0.5 步长的细刻度。
- SVG 里 y 轴最小刻度会和 x 轴首个标签撞行（都贴底），靠 `pad` 的 PB 留白解决；参考线标签放左侧、离 y 轴刻度 30px，否则看起来像「0.30 参考 0.3」。

### 看效果：本地截图

```bash
# 整页 + 定位到某个区块（卡片、图表这类 JS 渲染出来的区块只能这么截）
python tools/shot.py _shots/card-mobile.png ".card" 390 640
python tools/shot.py _shots/eq-desktop.png "#eqw" 1200 760

```

Chrome headless 的 `--screenshot` 只拍视口，页面很长时抓不到下半部分；`--window-size=390` 还会被最小窗口宽度顶到 497，
看着像横向溢出（实际没有）。

`shot.py` 把页面塞进 iframe、把目标元素顶到视口顶端（用**负 margin**，不是 `scrollTo`）。三个坑：

- 大部分区块是 **class 不是 id**（`.grid` / `.mchart`），`index.html#mchart` 找不到元素就停在页首，截出来完全无关。
- file:// 下每个文件都是独立 origin，父页拿不到 `iframe.contentDocument` → 必须加
  `--allow-file-access-from-files`（否则定位脚本静默失效，也永远停在页首）。
- 用 `scrollTo` 也不稳：`--virtual-time-budget` 下滚动常常在截图之后才生效。
- **iframe 高度必须拉到整页高度**（`scrollHeight+40`）。原来写死成视口的 4 倍，
  分数历史图在 y≈2600 处：定位把它推到 iframe 之外，拍出来是一张**纯背景色的空白图**，
  十几 KB、看不出错 —— 2026-10-24 为此白截了三张。

`peek.py` 是另一条路：把目标 `<div>` 单独摘出来、套上原 CSS 渲染，**没有时序问题**，图多高就多高。
静态区块（labs、近一月对比图）优先用它；卡片是 JS 渲染的，只能走 `shot.py`。
